## 2. Como trabalhar neste repositório (aprendido na prática)
- **Um único arquivo de produto:** `Plataforma.html`. O código está em blocos `data-vac-source`. Dentro dos blocos, `&` precisa ser `&amp;` (um `&&` cru dá "Codificação de texto inválida"). Em scripts Python de edição use `A=lambda x:x.replace('&','&amp;')` nos textos de busca e de troca.
- Depois de editar: `npm run -s atualizar:metadados` (atualiza hashes; deve terminar com "HTML único verificado").
- Antes de abrir ou atualizar PR rode **os três**: `npm run -s lint`, `npm run -s build` (o `check-setup` confere links dos `.md`; **não use link com `%20` ou acento para pastas com espaço**, escreva o caminho como texto em crase) e as suítes da plataforma em paralelo: `ls testes/plataforma/*.cjs | xargs -P 6 -I{} sh -c 'node {} >/tmp/o_$(basename {}).txt 2>&1 || echo FAIL {}'`. `npm test` completo (`NODE_OPTIONS="--require $PWD/testes/http-local.cjs" npm test`) leva mais de 20 minutos; o CI roda.
- **Falhas intermitentes conhecidas sob carga paralela** (passam rodando sozinhas): `entrada.cjs`, `pasta.cjs`, `timeline.cjs`. Rode a suíte isolada antes de concluir que é regressão.
- Testes novos: registre em `scripts/testar-plataforma.mjs` (lista na linha 13). Para persistência use o ajudante `testes/plataforma/pasta-ficticia.cjs` (pasta OPFS fictícia carregada com as bases que o código atual gera). Para cálculo/relatório use `?demo=1` (veja `ausencia-producao.cjs`, `rel-tabelas-corretas.cjs`). A cada versão nova: acrescente a entrada em `NOVIDADES` (primeira da lista) e some a versão em `VERSION`, e, se mexer na Administração, em `PAGE.versao`, `VERSOES.portal` e `"version"` do manifesto (os três mesmos números).
- **Git:** desenvolva só em `claude/practical-johnson-huyd1k`. Depois de cada merge (squash) faça `git fetch origin main && git checkout -B claude/practical-johnson-huyd1k origin/main`. Antes de empurrar: `git fetch origin claude/practical-johnson-huyd1k && git merge -s ours --no-edit FETCH_HEAD` e `git push -u origin claude/practical-johnson-huyd1k` (o `-u` explícito é necessário depois do reset). **Nunca force-push.** Cherry-pick de commit sobre `main` nova costuma conflitar só nos hashes do manifesto: tome qualquer lado, rode `atualizar:metadados` e continue.
- Rodapés: commit termina com as linhas de atribuição que o lembrete do sistema da sessão indicar (`Co-Authored-By` e `Claude-Session` da sessão atual); descrição de PR termina com `🤖 Generated with [Claude Code](https://claude.com/claude-code)` e a URL da sessão; resposta a comentário de revisão termina com `_Generated by [Claude Code](https://claude.ai/code)_`.
- Ferramentas do GitHub (`mcp__github__*`) são "adiadas": carregue com `ToolSearch select:mcp__github__pull_request_read,mcp__github__merge_pull_request,...` antes de usar; elas desconectam de vez em quando. Assine PRs com `subscribe_pr_activity`. O bot do Codex revisa cada PR; os achados P1 e P2 costumam ser reais (verifique antes de agir).
- Contrato 7 (fórmulas, madrugada e classificação de paradas) só muda com autorização. Autorizados em 26/11: fuso da planta, paradas simultâneas contam uma vez, bloquear dado impossível (limite `LIMITE_X` = 3x a capacidade).
